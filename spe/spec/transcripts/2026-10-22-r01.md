## Prompt

I want to create an MCP server for Google Photos. Here's my use case:
<use_case>
* I want to be able to take pictures on my Android phone, which automatically upload to Google Photos immediately
* I want to be able to tell Claude (or any agent using this MCP server) to look up such and such a photo (one or many) on Google Photos
* Claude should be able to look up the photos using whatever metadata is available via the API (incl. location metadata)
* Claude should be able to download those photos to a TMP folder (the same way that Claude Code currently processes images that are dragged into the terminal in CLI) to analyze in the context of the chat
* I don't want Claude to permanently download these images, but rather to get them in a tmp-compliant manner that allows them to simply be referenced via Claude Code and then disposed of in whatever way normal images in Claude sessions are 
</use_case>
<example_workflows>
* I'm working on a photogrammetry project in Claude Code and head outside to snap a few hundred images of an object, then come back inside and ask Claude to ingest them.
* I'm taking pictures of a slide deck someone is presenting in-person and asking Claude to take notes for me live without me having to upload them.
* I take snapshots of diagrams or daily journals and ask Claude to convert them to mermaid diagrams or markdown files.
</example_workflows>
<reference_architectures>
* I have a Google Health MCP that already uses Google OAuth and works well. It's deployed via Cloudflare, so while the API(s?) for Google Photos are surely different, I would love for the auth, security, deployment, and connection approach to mirror this where possible.
</reference_architectures>
<methodology>
I want to leverage the SPE Loop to build this, where evals are testing the ideal paths for perfect, flexible, optimized MCP servers for this use case. Assume we are running whatever the default model is, in this case Opus 5.5. I don't care too much about testing different Claude models, only different MCP designs/configurations/prompts/resources, etc.
</methodology>
